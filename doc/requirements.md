# 需求规格说明

## 一、需求根源

核心痛点源于 **"多任务上下文切换的认知负担"**。

在 AI 协作场景下，用户同时开启多个对话窗口，形成多个并行的"思维线程"。由于 AI 生成内容需要时间，用户被迫在任务间频繁切换。这种高频切换导致工作记忆（短期记忆）过载，具体表现为：

1. **目标迷失**：回到某个窗口时，忘了当初开启对话的具体目的
2. **任务遗忘**：AI 已输出完毕，但自己彻底忘了曾开启过这个任务
3. **管理混乱**：当窗口堆叠（如十几个浏览器标签或客户端窗口）时，缺乏视觉索引，难以快速定位

**本质**：为操作系统层面的"窗口对象"赋予临时的"语义标记"，将短期记忆外挂在可视化界面上。所有数据仅会话内有效，程序退出即清除。

## 二、核心目的

开发一个 **"外挂式窗口语义增强工具"**。它不改变 AI 应用本身，而是在 Windows 窗口管理之上增加一层**元数据图层**。最终目标是：**让用户随时了解每个窗口"正在执行什么命令、目的是什么"，通过自定义标签和便签，秒级恢复工作上下文。**

## 三、功能模块详细拆解

### 1. 窗口感知与定位

| 功能 | 说明 |
| :--- | :--- |
| 自动检测当前活动窗口 | 监听窗口切换事件 (`SetWinEventHook`) |
| 窗口唯一标识 | 以窗口句柄（HWND）为唯一标识，仅会话内有效 |
| 窗口状态追踪 | 窗口关闭时自动移除标记，无需持久化或继承 |

### 2. 标签与便签 UI 层

| 功能 | 说明 |
| :--- | :--- |
| 左上角悬浮标记 | 在被标记窗口的左上角绘制醒目的颜色标记（小圆点或图标） |
| 悬停展开便签 | 鼠标悬停在标记上时，弹出便签浮窗。包含：**标题**（必填）和**备注**（选填） |
| 标记编辑/删除 | 在展开的便签中提供"修改"和"移除标记"按钮 |
| 窗口激活反馈 | 切换到已标记窗口时，标记短暂闪烁或高亮提醒 |
| 快捷键快速添加 | 通过快捷键（如 `Ctrl+Shift+N`）对当前活动窗口快速添加标签，无需打开面板 |

### 3. 全局概览面板

| 功能 | 说明 |
| :--- | :--- |
| 聚合列表视图 | 快捷键（如 `Ctrl+Shift+M`）调出主界面，列表/网格展示所有已标记窗口 |
| 快速跳转 | 点击列表项自动激活（`BringToFront`）对应窗口 |
| 搜索/过滤 | 支持按标题关键词搜索，快速筛选任务 |

## 四、关于数据持久化

### 不做持久化的原因

**系统重启后，窗口还是原来那个窗口吗？** 答案是否定的。Windows 窗口句柄（HWND）在进程创建时动态分配，系统重启后即使打开"同一个"应用，窗口句柄也完全不同。即使通过进程路径等技术手段可以匹配到"同一个窗口"，但该窗口内的工作进度（如 AI 对话内容）已被清空，此时继承旧标签毫无意义。

因此，WinTag 采取**纯会话内存储**策略：
- 所有标签数据仅存在于内存中
- 程序退出或窗口关闭时，数据自动清除
- 无需数据库、无需文件 I/O、无需序列化

## 五、非功能需求

- **性能**：覆盖层位置同步延迟 < 50ms，CPU 占用 < 5%
- **可靠性**：窗口关闭时正确清理覆盖层，不泄漏 GDI 资源
- **兼容性**：支持 Windows 10/11，高 DPI 缩放（125%、150%、200%）
- **安全性**：不注入目标进程，仅使用标准 Windows API
