# 开发计划

## 技术选型

| 层面 | 选择 | 理由 |
| :--- | :--- | :--- |
| 语言 | Rust | 内存安全、windows-rs 日趋成熟、Cargo 构建方便 |
| 系统 API | windows-rs | 官方推荐的 Rust Win32 绑定 |
| 存储 | SQLite (rusqlite) | 轻量、无需安装、嵌入式 |
| GUI | egui 或 Tauri | egui 即时模式性能好；Tauri 可利用 Web 技术建漂亮 UI |
| 构建 | Cargo | Rust 标准构建工具 |

## 分阶段路线图

### 阶段一：MVP（1-2 周）

**目标**：跑通核心流程，能用就行

- [ ] 搭建 Rust 项目骨架，确定目录结构
- [ ] 实现窗口检测：获取当前活动窗口的标题、进程名、句柄
- [ ] 实现全局热键注册（`Ctrl+Shift+M`）
- [ ] 实现 SQLite 存储：创建表、CRUD 操作
- [ ] 实现简单的命令行/基础 GUI 概览面板（列表显示所有标记窗口）
- [ ] 实现"标记当前窗口"的基本流程（热键 → 弹出输入框 → 保存）
- [ ] 托盘图标，程序常驻后台

**验证标准**：能通过热键标记窗口，能通过热键呼出面板查看所有标记

### 阶段二：核心体验（2-3 周）

**目标**：覆盖层上线，体验完整

- [ ] 攻克透明覆盖层技术：创建穿透式置顶窗口
- [ ] 实现标记圆点在窗口左上角显示
- [ ] 实现覆盖层位置同步（监听 `EVENT_OBJECT_LOCATIONCHANGE`）
- [ ] 实现高 DPI 适配
- [ ] 实现鼠标悬停展开便签浮窗
- [ ] 实现标记编辑和删除功能
- [ ] 实现窗口激活闪烁反馈
- [ ] 实现窗口重开后的标签自动继承

**验证标准**：标记在目标窗口上可见，悬停可查看/编辑，窗口移动时标记跟随

### 阶段三：完善（1 周）

**目标**：打磨细节，处理边缘情况

- [ ] 全局搜索过滤功能
- [ ] 多显示器适配
- [ ] 最小化窗口时隐藏标记
- [ ] 全屏应用降级处理
- [ ] 管理员权限窗口兼容
- [ ] 性能优化与内存泄漏检查
- [ ] 错误处理完善
- [ ] 用户配置（热键自定义、默认颜色等）

**验证标准**：在多种边缘情况下稳定运行，无内存泄漏

## 里程碑

| 里程碑 | 预计时间 | 交付物 |
| :--- | :--- | :--- |
| M1: 项目搭建 | 第 1 周 | 可编译运行的基础框架 + 窗口检测 |
| M2: MVP | 第 2-3 周 | 可用的标记+存储+面板 |
| M3: 覆盖层 | 第 4-5 周 | 窗口上可见标记和便签 |
| M4: 发布 | 第 6 周 | 完整功能，可日常使用 |

## 风险与对策

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| 覆盖层在某些窗口上无法显示 | 高 | 提前测试各类窗口（浏览器、IDE、终端），必要时请求管理员权限 |
| 高 DPI 下坐标偏移 | 中 | 早期就引入 DPI 适配，不要拖到后期 |
| windows-rs 文档不足 | 中 | 参考 C++ Win32 示例，通过 FFI 转换到 Rust |
| 性能问题（CPU 占用高） | 低 | 使用事件驱动而非轮询，早期做性能测试 |
