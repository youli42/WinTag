# 开发计划

## 技术选型

| 层面 | 选择 | 理由 |
| :--- | :--- | :--- |
| 语言 | Rust | 内存安全、windows-rs 日趋成熟、Cargo 构建方便 |
| 系统 API | windows-rs | 官方推荐的 Rust Win32 绑定 |
| 存储 | 标签：内存 HashMap（仅会话内）；配置：TOML 文件（`%APPDATA%/WinTag/config.toml`，见 [D10](./decision-records.md)） | 标签仅会话内有效；UI 偏好（主题/圆角）持久化 |
| 图形界面 | 纯 Win32 原生窗口 | 覆盖层需区域级点击穿透（WM_NCHITTEST），egui/eframe 无法表达；已移除（见 [决策记录 D1](./decision-records.md)） |
| 构建 | Cargo | Rust 标准构建工具 |

## 分阶段路线图

### 阶段一：最小可行版本（1-2 周）

**目标**：跑通核心流程，能用就行

- [x] 搭建 Rust 项目骨架，确定目录结构
- [x] 实现窗口检测：获取当前活动窗口的标题、进程名、句柄
- [x] 实现全局热键注册（`Ctrl+Shift+M` 打开面板，`Ctrl+Shift+N` 快速标记）
- [x] 实现内存中标签存储（HashMap）和 CRUD 操作
- [x] 实现 Win32 概览面板（列表显示所有标记窗口、搜索、跳转）
- [x] 实现"标记当前窗口"的基本流程（热键 → 弹出输入框 → 保存到内存）
- [x] 实现覆盖层窗口创建（穿透式置顶透明窗口 + 橙色圆点）
- [ ] 托盘图标，程序常驻后台

**验证标准**：能通过热键标记窗口，能通过热键呼出面板查看所有标记，程序退出后数据消失

### 阶段二：核心体验（2-3 周）

**目标**：覆盖层上线，体验完整

- [x] 攻克透明覆盖层技术：创建穿透式置顶窗口
- [x] 实现标记圆点在窗口左上角显示
- [x] 实现覆盖层位置同步（监听 `EVENT_OBJECT_LOCATIONCHANGE` + 500ms 兜底轮询）
- [x] 实现高 DPI 适配（Per-Monitor V2）
- [x] 实现鼠标悬停展开便签浮窗
- [x] 实现标记编辑和删除功能（已有标签预填编辑）
- [ ] 实现窗口激活闪烁反馈

**验证标准**：标记在目标窗口上可见，悬停可查看/编辑，窗口移动时标记跟随，窗口关闭时标记自动清除

- [ ] 全局搜索过滤功能

- [ ] 最小化窗口时隐藏标记
- [ ] 全屏应用降级处理
- [ ] 管理员权限窗口兼容
- [ ] 性能优化与内存泄漏检查

- [ ] 用户配置（热键自定义、默认颜色等）— 已实现配置持久化与主题/圆角设置（设置页，见 [D10](./decision-records.md)）；热键编辑 UI 与默认颜色自定义待后续（见 [issues-and-requirements.md R1](./issues-and-requirements.md)）

## 风险与对策

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| 覆盖层在某些窗口上无法显示 | 高 | 提前测试各类窗口（浏览器、IDE、终端），必要时请求管理员权限 |
| 高 DPI 下坐标偏移 | 中 | 早期就引入 DPI 适配，不要拖到后期 |
| windows-rs 文档不足 | 中 | 参考 C++ Win32 示例，通过 FFI 转换到 Rust |
| 性能问题（CPU 占用高） | 低 | 使用事件驱动而非轮询，早期做性能测试 |
